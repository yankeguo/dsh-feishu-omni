## Summary (English)

`@yankeguo/dsh-feishu-omni` is a DeepSeek Harness (DSH) plugin that turns **one existing DSH Session** into a shared Feishu channel: multiple Feishu users talk to the same Session, see each other's messages and the assistant's final replies, and get a fixed `OK` reaction on their original message once it has been admitted. Final assistant replies are rendered as Feishu Card JSON 2.0 Markdown (headings, lists, code blocks, links, tables), and long replies are split across ordered cards. Images and files work in both directions through DSH's native `ImageBlock`/`FileBlock` and the existing `present` tool — **no new agent tools are added**. Publishing is staged: CI only stages, a maintainer approves on npmjs.com, and the GitHub Release is created manually afterwards.

## 功能概览

- **一个共享 Session，而不是每人一个 Session**：插件复用设置页里选中的**一个既有普通 DSH Session**（不自动创建 Session，排除 `origin: subagent` 的子 Agent Session），所有飞书单聊共享同一条消息流。飞书输入以 `[飞书 · 发送者]` 前缀进入 Session；DSH 网页中的人类输入以 `[DSH]` 前缀同步给所有绑定用户。
- **发送者不回显**：飞书用户消息的镜像广播给除发送者外的全部绑定用户，发送者本人不再收到自己刚发内容的重复回显，其他人仍能看到；图片/文件镜像遵循同一规则。解析不出发送方时宁可全量广播，可见性优先。
- **`OK` 表情回执**：消息成功进入 Session（prompt admission 成功且去重键已持久化）后，机器人给用户**原始消息**加一个固定的 `OK` 表情。best effort：一次尝试、不重试，失败只记日志，不影响投递与广播。
- **Markdown 卡片渲染**：助手最终回复使用飞书卡片 JSON 2.0 的 `markdown` 富文本组件渲染标题、列表、引用、代码块（含语言）、链接和表格，卡片标题保留 `[助手]`。长回复按最终请求体估算（每条 ≤ 24 KB）分片，用 `(i/n)` 标注顺序；优先在段落/代码围栏边界切分，代码围栏在分片处闭合/重开。卡片被飞书明确拒绝时用同一 `uuid` 回退为纯文本。
- **图片/文件双向、不新增 agent tool**：入站图片下载并经魔数校验后交给 DSH 附件服务，在 Session 中成为**原生 `ImageBlock`**；文件/音频/视频流式写入附件服务，成为**原生 `FileBlock`**（只读绝对路径），助手用现有 `Read`/`read_image`/office 工具读取。出站监听 `present` 的 `deliverables/presented`，在 `completed` 的 turn 先发助手卡片、再发文件/图片消息；助手 Markdown 里的本地图片引用会上传为 `image_key` 内联进卡片。`present` 已声明的同一图片不重复显示。
- **可靠性**：`message_id + event_id` 双键持久去重、Session 事件去重、机器人消息防回环；全局 FIFO、指数退避、发送 API `uuid` 幂等；SDK 自动刷新 tenant token、断线自动重连；单个收件人失败不阻塞其他收件人。
- **安全与隐私**：App Secret 存入 DSH credentials，状态接口、设置页和日志不返回明文；非秘密状态（绑定、最近去重键）写入 `state.json`，临时文件原子替换、权限 `0600`；出站只桥接 Session 工作区或 DSH 附件目录内的普通非空文件（`realpath` 收敛 + 严格前缀边界，根外一律拒绝且 fail closed），用于防止共享 Session 被 prompt 注入后外发本机任意文件。
- **设置与接入**：独立 Settings 页和 Plugin Manager 的 Configure 页均可使用（App ID/App Secret、Session 选择、连接状态、测试消息）；管理 RPC 复用 DSH 已认证的 `/api` 通道，不新增端口，不读取或重写 profile 的 `cordis.patch.yml`。中英文界面文案与图标随包发布。
- **依赖**：飞书官方 Node SDK `1.76.0` 的 WebSocket 长连接，无需公网 webhook、内网穿透或二维码流程；MIT 许可，第三方依赖与许可说明见 `THIRD_PARTY_NOTICES.md`。

## 飞书应用与权限

需要在飞书开放平台创建**企业自建应用**，启用机器人能力。文本 + 图片/文件功能的**最小权限**为五项：

| 权限 | 用途 |
| --- | --- |
| `im:message.p2p_msg:readonly` | 接收单聊用户消息 |
| `im:message:send_as_bot` | 以机器人身份发送消息（含 `text`/`interactive`/`image`/`file`） |
| `im:message.reactions:write_only` | 给用户原始消息添加 `OK` 表情回执 |
| `im:message:readonly` | 下载消息中的图片/文件资源（任一 `im:message` / `im:message:readonly` / `im:message.history:readonly` 可替代） |
| `im:resource:upload` | 上传图片/文件（任一 `im:resource` / `im:resource:upload` 可替代） |

事件订阅添加“接收消息 v2.0”（`im.message.receive_v1`），订阅方式选择**使用长连接接收事件**。只使用文本功能时前三项即可，后两项用于图片/文件。**权限和事件变更必须创建并发布新的应用版本后才生效**；缺权限时按能力降级（例如没有 `OK` 回执、图片/文件镜像降级为占位文本），文本链路和助手卡片不受影响。文档与官方依据见仓库 README。

## 已知限制

- **仅单聊**：不支持群聊；群 @ 机器人、合并转发、卡片消息里的资源也不处理。只支持一个共享 Session，子 Agent Session 不在选择范围内。
- **没有流式体验**：不推送流式 token、工具进度，不支持消息编辑/撤回、交互式卡片按钮、卡片审批、二维码流程、多机器人或多实例高可用。
- **客户端版本**：卡片 JSON 2.0 需要飞书客户端 **7.20+**；更低版本按官方行为只显示卡片标题与升级提示，不会把列表/代码块降级成纯文本 Markdown。
- **附件不自动清理**：入站与出站规范化的附件字节存入 DSH 附件服务（`$DSH_HOME/attachments/v1`，内容寻址），DSH 与插件都不会自动删除，长期使用需运维自行清理；清理后历史 `FileBlock` 的只读路径会失效。
- **资源大小**：> 100 MB 的资源下载不支持（飞书需 Range 分片）；入站图片插件上限 20 MB、文件上限 100 MB；出站图片上限 10 MB（GIF ≤ 2000×2000、其他 ≤ 12000×12000）、文件上限 30 MB，超限或上传失败时降级为文本提示。
- **单进程、无持久 outbox**：DSH 已提交但尚未完成飞书发送时若进程崩溃，不会自动补发；去重键有容量上限，极旧事件重投可能再次执行；不支持多实例部署。
- **大附件阻塞共享 FIFO**：附件下载/暂存/上传在单一 FIFO 内完成，单个大附件会推迟其他用户的消息与助手回复。
- **镜像为 best effort**：其他绑定用户看到的图片/文件依赖同一应用重新上传；缺 `im:resource:upload`、超限或重试耗尽时降级为占位文本。表情回执同为 best effort。
- **`present` 依赖 preset**：出站交付物要求绑定 Session 的 agent preset 挂载了 `present` 工具；minimal preset 可能没有，但助手 Markdown 内联图片仍可用。
- **模型视觉能力**：图片是否真正被理解取决于上游模型的 `inputModalities`；不支持图片时插件给发送者文本提示，Session 不接收该附件。
- **出站路径范围**：`present` 交付物与卡片内联图片只允许 Session 工作区或 DSH 附件目录内的文件；其它位置需先复制进工作区，否则只收到不含本机路径的降级提示。
- **回显抑制兜底**：旧格式请求或绑定在 prompt 与事件之间刷新等边缘情况可能偶发一次回显；正常新消息不回显。
- **未在真实飞书验证的部分**：自动测试使用 fake 飞书网关、fake Session 与临时目录，**不访问真实飞书，也不安装到运行中的 DSH**。真实租户的权限发布生效、卡片渲染、`OK` 表情、限频、旧客户端显示、附件与交付物在客户端的表现等，请按 README 的“人工验收（需要真实飞书应用）”清单逐项确认。

## 安装

**在 npmjs.com 网页 approve 之后**，`0.1.0` 成为 `latest`，可按版本或默认安装：

```sh
dsh plugin --profile desktop add @yankeguo/dsh-feishu-omni@0.1.0
# 或省略版本（approve 后 latest 即 0.1.0）：
dsh plugin --profile desktop add @yankeguo/dsh-feishu-omni
```

也可以在 DSH Web 的 **Plugins → Add plugin** 中输入 `@yankeguo/dsh-feishu-omni`。

**approve 之前**（npm 上尚无该包）从源码目录安装：

```sh
git clone https://github.com/yankeguo/dsh-feishu-omni.git
cd dsh-feishu-omni
pnpm install
pnpm build
```

然后在 **Plugins → Add plugin** 的 spec 文本框粘贴该仓库目录的**绝对路径**；`lib/` 被 `.gitignore` 排除，全新 clone 必须先 `pnpm build`，否则插件激活时无法 import `lib/index.js`。首次安装可能因 `@larksuiteoapi/node-sdk` 的传递依赖 `protobufjs` 需要批准安装脚本（`ERR_PNPM_IGNORED_BUILDS`），在安装对话框点击“允许这些脚本并重试”即可；替换已安装包需要重启 DSH。

**兼容性**：开发与测试基准为 **DSH `0.2.2-rc.5`**，`engines.dsh` 为 `>=0.2.2-rc.5 <0.3.0`；Node.js `>=24.9`，pnpm `12.x`。CI 使用 Node 24；发布 workflow 固定 pnpm `12.16.1` 与 npm `11.20.0`（staged publishing 需要 npm ≥ 11.15.0）。
