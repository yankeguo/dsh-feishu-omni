# 人工验收清单（真实飞书租户）

本文面向**维护者 / 验收者**：自动测试只使用 fake 飞书网关、fake Session 和临时目录，
**不访问真实飞书，也不安装到正在运行的 DSH**；因此真实平台行为（权限发布生效、卡片渲染、
`OK` 表情、限频、旧客户端、附件与交付物在客户端的表现等）必须在真实租户里人工确认。

自动化证据（单元/集成测试、单包发布不变式、打包预检）见
[DEVELOPMENT.md](DEVELOPMENT.md) 与 [releases/v0.1.0.md](releases/v0.1.0.md)；本文只列
真实平台的人工验收项。

## 1. 前提与准备

- [ ] 已按 [README](../README.md#安装) 完成安装；替换已安装包后**已重启 DSH**（Host JS 与
      助手卡片改动都需要重新构建并重启才会在运行中的进程里生效）。
- [ ] 已在飞书开放平台完成企业自建应用、机器人能力、权限申请、事件订阅与**版本发布**
      （见 [README](../README.md#飞书应用配置)）。
- [ ] 绑定的是一个**普通 DSH Session**（不是子 Agent Session）；做交付物验收时，该 Session
      的 agent preset 已挂载 `present` 工具（标准 preset 默认有）。
- [ ] 准备两个飞书账号 **A / B**（都在应用可用范围内，且都能私聊机器人）。
- [ ] 记录验收环境：日期、DSH 版本、插件版本、飞书客户端版本、租户、操作系统。

## 2. 安装与设置页

- [ ] 开发机上 `pnpm install && pnpm run verify` 全部通过（环境搭建见 [DEVELOPMENT.md](DEVELOPMENT.md)）。
- [ ] 在全新 clone 中先执行 `pnpm install && pnpm build`，确认生成 `lib/`，再在
      **Plugins → Add plugin** 的 spec 文本框粘贴仓库目录的**绝对路径**。
- [ ] 首次从源码目录安装若出现 `ERR_PNPM_IGNORED_BUILDS`，安装对话框列出待批准脚本，
      点击“允许这些脚本并重试”后安装能够继续。
- [ ] Add plugin 后，插件条目显示名称、说明和图标，无加载错误。
- [ ] 独立 **Settings → 飞书 Omni** 页面和 Plugin Manager 的 Configure 页面均可打开。
- [ ] 保存无效凭据时出现可理解错误，页面和日志没有 Secret 明文。
- [ ] 保存有效凭据并选择 lead Session 后，状态变为**已连接**。
- [ ] 飞书后台可以选择长连接并保存 `im.message.receive_v1` 订阅。

## 3. 文本链路、回显与表情回执

- [ ] 用户 A 私聊后，A 的绑定出现；用户 B 私聊后，A 也能看到 B 进入 Session 的消息。
- [ ] 用户 A 发一条消息后，A **不会**收到自己刚发内容的镜像回显，且 A 的原消息出现
      `OK` 表情；用户 B 仍能看到 A 的消息（`[飞书 · 发送者]` + 原文）。A 发出的下一条消息
      同样不回显。
- [ ] DSH 网页中的人类输入（`[DSH]`）仍广播给 A、B 全部绑定用户；助手最终回复的广播与
      渲染不变。
- [ ] 未添加 `im:message.reactions:write_only`（或已添加但未发布新应用版本）时，消息仍正常
      进入 Session 并广播，只是没有 `OK` 表情；日志出现可辨识的权限警告。
- [ ] 表情回执失败（例如缺权限、消息在回执前被撤回）只出现在日志里，不改变 Settings 的
      连接状态/最近错误，也不影响消息投递与广播。
- [ ] DevLead 的最终回复同时到达 A、B；工具调用和流式 token 不刷屏；取消、失败或
      `max-tokens` 截断的 turn 不广播半截回复。
- [ ] 同一消息重复投递不会重复进入 Session，也不会重复添加表情回执；网页中的人类输入也会
      同步。
- [ ] 断网再恢复后 SDK 自动重连；终态错误可在设置页查看并手动重新连接。
- [ ] 一个会话投递失败不妨碍另一个会话，恢复后下一条消息可再次送达。
- [ ] 断开后飞书消息不再进入 Session，重新连接后恢复。

## 4. 助手卡片渲染与分片

- [ ] 助手回复的 Markdown 在飞书内正确渲染：标题、加粗、斜体、删除线、列表、引用、
      代码块（含语言高亮）、链接、表格；卡片标题显示 `[助手]`。
- [ ] 让助手输出一段很长（例如超过 30 KB）的回复（多个段落 + 长代码块 + 引号密集文本），
      确认被拆成多条 `[助手] (i/n)` 卡片、顺序正确、代码围栏在分片处正确闭合/重开，
      没有半截代码块。
- [ ] 用低于飞书客户端 7.20 的旧版打开助手卡片：确认标题仍在、正文显示升级提示
      （已知限制，不会降级为纯文本 Markdown）。

## 5. 图片与文件

- [ ] **入站图片**：A 发一张 PNG/JPEG 图片，A 的原消息出现 `OK` 表情；Session 中助手能
      描述图片内容（所选模型需支持视觉）；B 收到同一张图片消息，A 自己不再收到图片回显。
- [ ] **入站文件**：A 发一个 PDF，Session 中助手能读到文件内容（FileBlock 只读路径）；
      B 收到该文件消息。音频/视频按文件处理。
- [ ] **入站降级**：A 发 HEIC/BMP/TIFF 图片或 > 20 MB 图片，A 收到明确的文本提示且没有
      `OK` 表情，Session 中不出现该消息，B 也收不到；发 > 100 MB 文件同理。
- [ ] **出站交付物**：让助手用 `present` 发布一个文件和一个图片，turn 完成后 A、B 都先收到
      助手卡片、再收到文件/图片消息（图片显示为图片而不是文件）。
- [ ] **卡片内联图片**：让助手在最终回复里用 `![说明](<本地路径>)` 引用一张图片，卡片中
      直接显示图片而不是本机路径；`present` 已声明过的同一图片不重复显示。
- [ ] **出站降级**：present > 30 MB 文件时各绑定收到文本降级（文件名+大小+原因，不含本机
      路径）；present > 10 MB 图片时经 DSH 规范化后仍能作为图片显示。
- [ ] **附件权限**：未添加/未发布 `im:message:readonly` 时发图片，发送者收到降级提示、
      文本链路正常、日志有可辨识权限警告；未添加/未发布 `im:resource:upload` 时，其他绑定
      镜像与出站交付物降级为占位/文本，助手卡片与文本消息正常。
- [ ] **双用户可见性**：A 发的图片/文件 B 能看到、A 不回显；助手回复/交付物里的图片与文件
      A、B 都能看到。

## 6. 安全：出站路径收敛（防注入外发）

- [ ] 让助手 `present` 一个工作区外的文件（例如 `/etc/hosts`），各绑定只收到
      「文件不在会话工作区或 DSH 附件目录内」文本降级，不含绝对路径、没有文件消息。
- [ ] 让助手在回复里写 `![x](/etc/hosts)`，卡片保留原 Markdown 文本、不上传图片。
- [ ] 把同一文件复制进 Session 工作区后再 `present`/引用，应正常发送。

## 7. 记录与后续

- [ ] 记录环境与逐项结果（日期、DSH/插件/客户端版本、租户、每项通过/失败、关键日志片段）。
- [ ] 失败项写清现象、脱敏后的日志摘要与复现步骤，并同步到下一次
      [release notes](releases/) 的“已知限制”与“未在真实飞书验证的部分”。
- [ ] 首发（`0.1.0`）之后的每个版本，发布前按 [PUBLISHING.md](PUBLISHING.md) 第 9 节复核
      首次 CI 运行/发布检查项；日常回归跑自动化校验
      （`pnpm run verify`、`pnpm run check:packages`、`pnpm run release:dry`）。
